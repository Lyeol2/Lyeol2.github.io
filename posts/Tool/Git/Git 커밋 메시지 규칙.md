## 1. 기본 형식

```
타입: 커밋 내용 요약
```

예시:

```
feat: 로그인 기능 추가
fix: 회원가입 시 이메일 검증 오류 수정
docs: README 설치 방법 추가
```

---

## 2. 커밋 타입

|타입|의미|예시|
|---|---|---|
|`feat`|새로운 기능 추가|`feat: 게시글 작성 기능 추가`|
|`fix`|버그 수정|`fix: 로그인 실패 시 에러 메시지 수정`|
|`docs`|문서 수정|`docs: API 사용법 문서 추가`|
|`style`|코드 스타일 변경|`style: 들여쓰기 및 공백 정리`|
|`refactor`|코드 리팩토링|`refactor: 회원 조회 로직 분리`|
|`test`|테스트 코드 추가/수정|`test: 로그인 서비스 테스트 추가`|
|`chore`|기타 설정/빌드/패키지 작업|`chore: eslint 설정 추가`|
|`design`|UI/디자인 변경|`design: 메인 페이지 버튼 스타일 수정`|
|`rename`|파일/폴더 이름 변경|`rename: user 폴더명을 member로 변경`|
|`remove`|파일/코드 삭제|`remove: 사용하지 않는 이미지 파일 삭제`|
|`perf`|성능 개선|`perf: 이미지 로딩 속도 개선`|
|`build`|빌드 관련 변경|`build: webpack 설정 수정`|
|`ci`|CI/CD 설정 변경|`ci: GitHub Actions 배포 스크립트 추가`|

## 3. 커밋 메시지 작성 규칙

### 1) 제목은 짧고 명확하게 작성하기

좋은 예:

```
feat: 댓글 작성 기능 추가
```

```
수정함작업함버그 고침
```

“뭘 했는지”가 바로 보여야 해.

---

### 2) 한 커밋에는 한 가지 작업만 담기

좋은 예:

```
feat: 로그인 기능 추가fix: 로그인 실패 메시지 수정docs: 로그인 API 문서 추가
```

나쁜 예:

```
feat: 로그인 기능 추가 및 버그 수정 및 문서 작성
```

한 커밋에 이것저것 다 넣으면 나중에 되돌리기 힘들어져 🫠

### 3) 제목 끝에 마침표 쓰지 않기

```
fix: 검색 결과 정렬 오류 수정
```

이렇게 쓰면 충분해.

---

## 4. 상세 설명이 필요한 경우

큰 작업이거나 이유를 남겨야 하면 아래처럼 작성해.

```
타입: 커밋 내용 요약
상세 설명 작성
- 왜 변경했는지
- 어떤 부분이 바뀌었는지
- 주의할 점이 있는지
```

예시:

```
refactor: 회원 인증 로직 분리
기존에는 컨트롤러에서 인증 검증을 직접 처리하고 있었음.
재사용성을 높이기 위해 인증 관련 로직을 별도 서비스로 분리함.
```
